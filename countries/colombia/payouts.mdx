## Overview

Create outbound payouts from **COP** accounts with `POST /api/v1/co/transactions/outbound`.

Omit `destinationType`, or send `bank`, for a bank payout (Fast Pay / ACH). Send `breb_key` or `breb_qr` for Bre-B.

The amount plus the outbound fee must fit the **net balance**. A successful create returns `201` with `id` and `status: processing`.

## Prerequisites

- Bearer API token with access to the COP account
- For bank payouts, a `bankCode` from `GET /api/v1/co/banks`

## List banks

`GET /api/v1/co/banks` returns `{ "banks": [...] }`. Each bank has `code`, `name`, `accountTypes`, `fastPay`, and `ach`.

`bankCode` is the 4-digit `code`. The bank must support Fast Pay or ACH, and it must list the `accountType` you send.

## Amount

`amount` is required for every destination.

Send `amount` as a string with at most 2 decimal places. A string with more than 2 decimal places returns `400` with `error: "Validation failed"` and `details` for field `amount` (`Invalid amount format`).

A JSON number with more than 2 decimal places is accepted and truncated toward zero to 2 decimal places. `1.239` becomes `1.23`. If the truncated value is not greater than zero, the API returns `400` with `error: "Validation failed"` and `details` for field `amount` (`Amount must be positive`).

## Destinations

### Bank (Fast Pay / ACH)

Required: `accountId`, `amount`, `accountType`, `bankCode`, `accountNumber` (max 20 characters), `beneficiaryFullName`, `documentType`, `documentNumber`.

`accountType`:

| Code | Label |
| --- | --- |
| `cc` | Checking |
| `ch` | Savings |
| `dp` | Electronic deposit |

### Bre-B key

`destinationType: breb_key`, plus `keyValue`, `beneficiaryFullName`, `documentType`, and `documentNumber`. Do not send bank fields.

### Bre-B QR

`destinationType: breb_qr`, plus `qrValue` (EMV or base64). `beneficiaryFullName` is optional. Omit `documentType` and `documentNumber` together, or send both. Sending only one is `400`. If the QR encodes a fixed amount, `amount` must match or the API returns `400` with `code: BREB_QR_AMOUNT_MISMATCH`. That body includes `details.qrAmountCents` and `details.requestedAmountCents`. It does not include `id`. A cancelled transaction row remains.

## Document types

| Code | Label | Number format |
| --- | --- | --- |
| `cc` | Citizenship ID | Digits only |
| `nit` | NIT | Digits only |
| `ce` | Foreign ID | Digits only |
| `pa` | Passport | Alphanumeric |
| `ppt` | PPT | Alphanumeric |
| `ti` | Identity card | Digits only |
| `rc` | Birth certificate | Digits only |
| `te` | Foreign card | Digits only |
| `die` | Foreign identification document | Digits only |
| `nd` | No document (Nequi) | Must be `ND` |

`nd` is bank-only, only for bank code `1507`. `documentNumber` must be `ND`, and `phone` (E.164) is required. `nd` is rejected on Bre-B key and Bre-B QR.

## Optional fields

On all three destinations: `phone` (E.164), `email`, `description` (max 40 characters), `webhookUrl`.

## Flow

1. `GET /api/v1/co/banks` when the destination is a bank account
2. `POST /api/v1/co/transactions/outbound`
3. Poll `GET /api/v1/co/transactions/{id}/status` or set `webhookUrl` — see [Receiving webhooks](/developers/receiving-webhooks)

Status polling is **outbound only**. It returns `id`, `externalID`, `status`, `direction`, `amount` (string), `currency`, and `providerStatus` when a refresh happened. It also includes `feeBreakdown` when a fee snapshot is stored: `platformFee`, `transactionFee`, `flatFee` (including `source`), and `collectedAmount`. The response omits `feeBreakdown` when there is no snapshot. A transaction that is not an outbound payout returns `400`. A refresh failure returns `502` with `error`, `code`, and `type`.

## Example (bank)

```bash
curl -X POST https://hg.cash/api/v1/co/transactions/outbound \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "accountId": "YOUR_ACCOUNT_UUID",
    "amount": "50000.00",
    "accountType": "cc",
    "bankCode": "1001",
    "accountNumber": "0000000001",
    "beneficiaryFullName": "Ana Ejemplo",
    "documentType": "cc",
    "documentNumber": "1000000000",
    "description": "Supplier payment"
  }'
```

```bash
curl -X POST https://hg.cash/api/v1/co/transactions/outbound \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "accountId": "YOUR_ACCOUNT_UUID",
    "amount": "10000.00",
    "accountType": "ch",
    "bankCode": "1507",
    "accountNumber": "3000000000",
    "beneficiaryFullName": "Ana Ejemplo",
    "documentType": "nd",
    "documentNumber": "ND",
    "phone": "+570000000000"
  }'
```

Bank `1507` accepts savings (`ch`) and electronic deposit (`dp`).

## Payout lifecycle

The payout starts in `processing` and moves to `done` when it settles, or `cancelled` when it is rejected.

`POST /api/v1/co/transactions/outbound` can return `502` with `error`, `code: CO_OUTBOUND_PROVIDER_CREATE_FAILED`, and `type: provider_error`. The body does not include `id`. The public `error` string is `Unable to complete this payout with the payment provider.` If the account cannot start the payout, or the destination cannot be registered, the transaction is `cancelled`. If the payout was submitted and the result is not confirmed, the transaction stays `processing`.

If the account cannot cover the amount and the outbound fee, the API returns `409` with `code: INSUFFICIENT_NET_BALANCE`.

A non-COP account returns `400`.

## Account status

The source account must be **`Operativa`**. **`Bloqueada`** or **`Cerrada`** returns `403` with `code: ACCOUNT_NOT_OPERATIVE`. **`Restringida`** returns `403` with `code: RESTRICTED`.
