## Overview

Colombia cash-in uses **hosted checkout** only. There is no `POST /api/v1/co/transactions/inbound`.

Create a session with `POST /api/v1/checkouts`, `country: "CO"`, `amount`, and `successUrl`. The response includes `checkoutUrl` and omits `checkoutUrlProvider`.

The payer opens `checkoutUrl`, completes payment, and returns to the HG success page. Your `successUrl` is used only after payment is confirmed.

HG configures the available payment methods. The create request does not choose them. Colombia does not require payer name, document, or email.

The account must use currency **COP** and be **`Operativa`**.

`GET /api/v1/checkouts`, `GET /api/v1/checkouts/{id}`, and `POST /api/v1/checkouts/{id}/cancel` omit `providerData` for Colombia.

## Prerequisites

- Bearer API token with access to the COP account
- A Colombia **COP** account with status **`Operativa`**

## Create body

Required:

- `country` — `"CO"`
- `amount`
- `successUrl`

Colombia does not require payer name, document, or email.

Optional: `accountId`, `cancelUrl`, `webhookUrl`, `metadata`, `reference`, `idempotencyKey`, `expiresInSeconds`, and `locale`.

`expiresInSeconds` is optional. The default is 86400 seconds. The maximum is 604800 seconds. `locale` is optional and is only `es` or `en`.

## Flow

1. `POST /api/v1/checkouts` with `country: "CO"`, `amount`, and `successUrl`
2. Send `checkoutUrl` from the response to the payer
3. The payer opens `checkoutUrl`, completes payment, and returns to the HG success page
4. After payment is confirmed, HG.Cash redirects the payer to your `successUrl`
5. Optionally set `webhookUrl` — see [Receiving webhooks](/developers/receiving-webhooks) and [Create checkouts](/checkouts/create)

## Example request

```bash
curl -X POST https://hg.cash/api/v1/checkouts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "CO",
    "accountId": "YOUR_ACCOUNT_UUID",
    "amount": "50000.00",
    "successUrl": "https://merchant.example/success",
    "cancelUrl": "https://merchant.example/cancel",
    "webhookUrl": "https://merchant.example/hooks/checkout",
    "reference": "ORD-42"
  }'
```

The checkout starts in `pending` and moves to `completed` when payment is confirmed.

After `expiresAt`, merchant get and list still return `status: pending`. The payer session reports `expired`. Cancelling a pending checkout still sets `cancelled`.

If the hosted session cannot be created, the API returns `502` with `error: "Failed to create CO payment with provider"`.

## Account status

The account must be **`Operativa`**. Requests against **`Bloqueada`** or **`Cerrada`** accounts return `403` with `code: ACCOUNT_NOT_OPERATIVE`. A **`Restringida`** account returns `403` with `code: RESTRICTED`. An account that is not ready for checkout returns `400` with `error: "Account is not ready for checkout"`. An account that is not a COP checkout account returns `400` with `error: "Account is not supported for this checkout country"`. That is separate from `400` with `error: "Account is not ready for checkout"`.
