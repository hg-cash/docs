## Painel

1. Abra **Checkouts** na barra lateral (`/app/checkouts`).
2. Revise a linha de **estatísticas** e as sessões recentes no resumo.
3. Em **Criar checkout**, escolha **país**, **conta** (opcional — a HG.Cash escolhe uma conta operativa elegível se omitida), **valor** e **URL de sucesso**.
4. Clique em **Criar checkout**. Copie o **link do checkout** no painel de sucesso e envie ao pagador.

Use **Validar** ou **Conciliar** (canto superior direito) quando precisar desses fluxos.

### Notas por país (painel)

| País | Campos extras na criação |
| --- | --- |
| **AR** | Nome e DNI do pagador opcionais; também pode informar na página hospedada |
| **BR** | **Nome do pagador**, **CPF/CNPJ (`document`)** e **e-mail** obrigatórios |
| **CL** | Por enquanto só via **API** (método de pagamento + dados do cliente) |
| **BO** | **Nome do pagador**, **CI/documento (`document`)** e **e-mail** obrigatórios |
| **CO** | Sem campos extras do pagador |

## API

**`POST /api/v1/checkouts`** com token Bearer. Corpo mínimo:

```json
{
  "country": "AR",
  "amount": "1500.00",
  "successUrl": "https://merchant.example/success"
}
```

Opcional: `accountId`, `cancelUrl`, `webhookUrl`, `metadata`, `idempotencyKey`, `locale` e `payer` (conforme o país).

Para **BR**, **CL**, **BO** e **CO**, se você informar um `accountId` explícito que esteja **`Bloqueada`** ou **`Cerrada`**, a API retorna `403` com `code: ACCOUNT_NOT_OPERATIVE`. Se omitir `accountId`, a HG.Cash seleciona uma conta **`Operativa`** elegível.

### Argentina (`AR`)

- A resposta inclui **`accountDisplay`** (alias, CVU/CBU, titular).
- O pagador preenche **nome**, **valor** e **DNI de 8 dígitos** na página hospedada.
- Conclusão quando uma transferência de entrada coincide valor + DNI na conta atribuída.

### Brasil (`BR`)

- **`payer.name`**, **`payer.document`** (CPF ou CNPJ — somente dígitos ou com pontuação) e **`payer.email`** obrigatórios na criação.
- A resposta pode incluir **`qrCode`** e **`pixCopiaECola`**.

### Chile (`CL`)

- **`paymentMethodId`** e **`customer`** obrigatórios — veja [Cash-in Chile](/pt-BR/countries/chile/cash-in) para listar métodos de pagamento.

### Bolívia (`BO`)

- **`payer.name`**, **`payer.document`** (CI ou documento do pagador) e **`payer.email`** obrigatórios na criação.
- A resposta pode incluir **`qrCode`** para o pagador escanear.

### Colômbia (`CO`)

- Somente checkout hospedado. Não existe `POST /api/v1/co/transactions/inbound`. Veja [Cash-in Colômbia](/pt-BR/countries/colombia/cash-in).
- Obrigatório: `country: "CO"`, `amount` e `successUrl`. Sem nome, documento ou e-mail do pagador.
- A HG configura os meios de pagamento disponíveis. A requisição de criação não os escolhe.
- A conta deve ser **COP** e **`Operativa`**.
- Opcional: `accountId`, `cancelUrl`, `webhookUrl`, `metadata`, `reference`, `idempotencyKey`, `locale`.
- A resposta inclui **`checkoutUrl`** e omite **`checkoutUrlProvider`**.
- `GET /api/v1/checkouts`, `GET /api/v1/checkouts/{id}` e `POST /api/v1/checkouts/{id}/cancel` omitem `providerData` para a Colômbia.
- O pagador abre `checkoutUrl`, conclui o pagamento e volta à página de sucesso da HG. Sua `successUrl` é usada somente depois que o pagamento é confirmado.
- **`Bloqueada`** ou **`Cerrada`** retorna `403` com `code: ACCOUNT_NOT_OPERATIVE`. **`Restringida`** retorna `403` com `code: RESTRICTED`. Uma conta que não está pronta para o checkout retorna `400` com `error: "Account is not ready for checkout"`.

## Exemplo (Brasil)

```bash
curl -X POST https://hg.cash/api/v1/checkouts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "BR",
    "amount": "100.50",
    "successUrl": "https://merchant.example/success",
    "payer": {
      "name": "Federico Autuori",
      "document": "957.937.532-14",
      "email": "fautuori@gmail.com"
    }
  }'
```

A resposta inclui **`checkoutUrl`** — envie essa URL ao pagador. Os campos PIX (`qrCode`, `pixCopiaECola`) também podem ser retornados na criação.

## Exemplo (Bolívia)

```bash
curl -X POST https://hg.cash/api/v1/checkouts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "BO",
    "amount": "150.00",
    "successUrl": "https://merchant.example/success",
    "payer": {
      "name": "Juan Pérez",
      "document": "12345678",
      "email": "payer@example.com"
    }
  }'
```

A resposta inclui **`checkoutUrl`** — envie essa URL ao pagador. Um **`qrCode`** (imagem base64) também pode ser retornado na criação.

## Exemplo (Colômbia)

```bash
curl -X POST https://hg.cash/api/v1/checkouts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "CO",
    "accountId": "YOUR_ACCOUNT_UUID",
    "amount": "50000.00",
    "successUrl": "https://merchant.example/success"
  }'
```

A resposta inclui **`checkoutUrl`** e omite **`checkoutUrlProvider`**. Envie `checkoutUrl` ao pagador. Não há endpoint de transação de entrada para a Colômbia.

## Exemplo (Argentina)

```bash
curl -X POST https://hg.cash/api/v1/checkouts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "AR",
    "amount": "1500.00",
    "successUrl": "https://merchant.example/success",
    "cancelUrl": "https://merchant.example/cancel",
    "webhookUrl": "https://merchant.example/hooks/checkout",
    "metadata": { "orderId": "ORD-42" }
  }'
```

A resposta inclui **`checkoutUrl`** — envie essa URL ao pagador.
